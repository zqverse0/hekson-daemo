# 《行舟入墨》展厅方案与工程架构

> 已确定：**平台为展厅大屏**；工程可以拆分为多模块；仓库已 `git init`；结局画卷要**便于展示、能吸引评委和观众**。
> 本文在《流程设计》的基础上补充展厅约束、体验时长、画卷展示方案和工程架构。两份文档冲突时，**时长、模式、画卷展示以本文为准**，幕内流程和分支以《流程设计》为准。

---

## 一、展厅大屏带来的约束

| 方面 | 约束 | 对设计的影响 |
|---|---|---|
| 停留时间 | 展厅单个互动项目通常停留 5–10 分钟 | 原设计 18–32 分钟太长，需要"展厅版"（见第二节） |
| 观看方式 | 一人操作，多人围观；观看距离 2–4 米 | 画面本身要好看，围观者不操作也能看懂；字号按远距离设计 |
| 输入 | 大屏触摸为主，现场可能有多人同时触碰 | 只响应第一个触点；按钮和手势起点要大；没有 hover |
| 声音 | 展厅嘈杂，可能有相邻展项 | 声音只做增强，关键信息（诗句）必须同时有画面；**取消麦克风"吹气"玩法**，只保留擦拭 |
| 网络 | 展厅网络不可靠 | **全部资源本地化**：字体自托管、音频本地、不依赖任何 CDN |
| 运行时长 | 每天连续运行 8–10 小时，无人值守 | 每一轮体验结束后重载页面，杜绝内存泄漏；崩溃自动恢复 |
| 硬件 | 固定的展厅电脑 + Chrome 全屏（kiosk）模式 | 只需适配 Chrome；可以使用 WebGL；但 4K 输出下 SVG 滤镜很贵，必须早测 |
| 画面比例 | 16:9 为主，可能是拼接宽屏 | 以高度为基准缩放（沿用 v3），横向安全区设计为 16:9，更宽时只延展背景 |

**待确认（影响开发，需要尽快问展厅方）**：屏幕分辨率与比例、是否触摸屏、主机配置（显卡）、是否有耳机或定向音箱、展厅是否有局域网。

## 二、三种运行模式

| 模式 | 时长 | 谁用 | 内容 |
|---|---|---|---|
| **游客版**（默认） | 约 10 分钟 | 普通观众 | 全部 8 段都走，但每幕只保留核心玩法；分支保留为"二选一"，不增加时长 |
| **评审演示版** | 约 6 分钟 | 讲解员带评委 | 按快捷键进入；关键交互由讲解员操作，其余自动推进；结尾展示三种不同画卷的对比 |
| **完整版** | 18–32 分钟 | 线上 / 后续 | 《流程设计》中的完整内容，展厅不默认开启 |

### 游客版时长分配

| 段落 | 时长 | 相对完整版的删减 |
|---|---|---|
| 序 · 琼林之约 | 50 秒 | 次韵只选一次（不是三次），直接决定心印 |
| 一 · 孤舟夜泊 | 90 秒 | 意象减为 4 个；支线二选一，只走一条 |
| 二 · 宜兴 | 2 分钟 | 四处地点只**选一处**深入，其余三处以 10 秒自动小景带过 |
| 三 · 归去来兮 | 70 秒 | 不变（本身就短） |
| 过场 · 万里长卷 | 40 秒 | 最多停靠一处驿站 |
| 四 · 不系之舟 | 100 秒 | 金山登高自动进行；人海听到 2 类即触发台词 |
| 五 · 着力即差 | 70 秒 | 不变 |
| 尾 · 舣舟 + 画卷 | 60 秒 | 时光轮盘自动转；漫游取消，直接进入画卷展示 |
| **合计** | **约 10 分钟** | |

### 无人操作时

- **20 秒无输入**：出现提示动画（一只淡墨的手示范动作）。
- **40 秒无输入**：当前手势自动完成，演出继续往下走（围观者仍能看完故事）。
- **90 秒无输入且处于探索段**：收卷，回到待机。
- 结局画卷展示完毕后 **15 秒**自动回到待机，并重载页面。

### 待机吸引

无人时大屏播放**众人长卷**（见第三节）：一幅很长的常州运河水墨长卷缓慢平移，岸上是之前所有观众留下的身影。画面中央一枚大朱印"展卷"，提示"触碰展卷"。

### 讲解员快捷键（游客看不到）

| 键 | 作用 |
|---|---|
| `F1` | 进入评审演示版 |
| `F2`–`F9` | 直接跳到第 0–7 段 |
| `F10` | 展示三种画卷对比 |
| `Esc` 长按 3 秒 | 立即回到待机 |
| `+` / `-` | 音量 |

## 三、画卷展示方案：个人长卷 + 众人长卷

### 1. 个人长卷：结局的高潮演出（约 40 秒）

1. 第五幕"舣舟"印落下后，画面拉远，玩家这一路的所有画面**拼接成一幅横向长卷**（构成规则见《流程设计》第五节）。
2. 镜头从卷首到卷尾**缓慢平移**。每经过一幕，那一幕的朱印**依次盖下**，伴随一声沉稳的印声，一共七声，形成节奏。
3. 平移到卷尾，镜头拉远，整幅长卷完整呈现在大屏上。这时题跋（由第三幕心境决定）逐笔写出。
4. 最后一方"舣舟"大印盖在卷尾。
5. 长卷卷起，变成一个小小的身影，飞向画面远处的运河岸边，**汇入众人长卷**。

### 2. 众人长卷：把观众变成"千万人随观之"

这是整个作品最适合向评委讲的点：

> 九百多年前，苏轼回到常州时，"千万人随观之"。
> 今天，每一位走进展厅、完成这段旅程的观众，都会成为运河岸边那千万人中的一个。

- 众人长卷是一幅不断变长的常州运河水墨长卷，画法与第四幕一致。
- 每位观众完成体验后，生成一个**专属的小身影**：外形由心印决定（山→戴笠者、水→撑伞者、竹→执竹杖者），衣上的朱点由选择的支线决定，旁边有一枚极小的编号印。
- 画面角落用书法数字显示累计人数："已有 〇〇〇〇 人随观"。
- 待机时播放众人长卷；结局时观众能看到自己的身影落在岸上，就在其他观众身旁。
- 随着展期推进，岸上的人越来越多，评委在不同时间来看，会看到不同的长卷。

### 3. 评审对比（F10）

三幅预先生成的画卷（心印山 / 水 / 竹，分支各不相同）上下并排展开，直观展示"同一结局，不同画卷"。

### 4. 后续可选：扫码带走

如果展厅有局域网或外网，结局可以显示一个二维码，观众用手机扫码保存自己的长卷长图。**依赖网络，放在第二阶段**，不影响主体验。

### 数据存储

- 单台大屏：众人长卷数据存在浏览器 IndexedDB 即可（只存每位观众的少量参数，不存图片，渲染时按参数现画）。
- 多台大屏或需要扫码：加一个局域网内的轻量 Node 服务，统一存储。
- 数据要能导出、备份；展期结束可以把整幅众人长卷导出成超长图，作为成果展示。

## 四、工程架构

### 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 构建 | **Vite** + 原生 JavaScript（ES Modules） | 开发服务器快，打包成纯静态文件可离线运行；不需要框架 |
| 框架 | 不用 React/Vue | 演出由 async 脚本驱动，画面由程序生成，框架带来的收益很小 |
| 线稿与交互 | SVG | 沿用 v3 的全部笔触与滤镜 |
| 大场景 | Canvas 2D 预渲染图层 | 远山、众人长卷、千人场景等先画成位图缓存，避免 4K 下实时滤镜 |
| 高负载兜底 | PixiJS（WebGL），**视原型结果决定** | 只有千人画卷原型在 Canvas 2D 下达不到 60fps 时才引入 |
| 音频 | Web Audio API | 环境声分层、硬切静音、吟诵时间轴同步 |
| 存储 | IndexedDB（单屏）/ 局域网 Node 服务（多屏） | 见第三节 |
| 运行 | Chrome `--kiosk`，本地静态服务器 | 不用 `file://` 打开，避免字体和模块加载限制 |

### 目录结构

```

├── CLAUDE.md
├── docs/                      # 设计文档（现有 5 份 md 移入）
├── prototypes/
│   ├── scene-01-sushi-v3.html # 原型参考，只读
│   ├── lamp-shadow/           # 灯影成字原型
│   └── crowd/                 # 千人画卷原型
├── public/
│   ├── fonts/                 # 自托管、按用字子集化的字体
│   └── audio/
├── src/
│   ├── main.js                # 启动、模式选择
│   ├── core/                  # rng、svg 工具、数学、tick、输入（单触点）、音频、存储
│   ├── ink/                   # 色板、滤镜 defs、笔触（taper/ridge）、景物（willow/pine/pavilion…）、人物 symbol、纸纹
│   ├── stage/                 # 世界长卷、视差图层、镜头
│   ├── cut/                   # 演出原语：shot/say/gesture/hold/drag/choose/camera
│   ├── transitions/           # T1–T7
│   ├── acts/                  # 每幕一个模块：00-prologue … 07-epilogue
│   ├── journey/               # 分支状态、默认值、模式（游客/评审/完整）
│   ├── scroll/                # 个人长卷合成、众人长卷
│   └── kiosk/                 # 待机、无操作计时、讲解员快捷键、重载与崩溃恢复
└── tools/                     # 字体子集化、众人长卷导出等脚本
```

### 幕模块接口

每一幕导出同样的结构，主流程按顺序调用：

```js
export default {
  id: 'night',                 // 段落 id，见下表
  title: '孤舟夜泊',
  seal: '残灯',                 // 印文；null 表示本段不钤印
  budget: { visitor: 90, full: 300 },   // 秒，用于无操作计时和节奏检查
  async run(ctx) {             // ctx: { journey, mode, cut, stage, audio, transitions }
    // 五拍：入画 → 主玩法 → 诗成 → 钤印 → 化印
  },
  scrollPiece(journey) {}      // 返回本段在个人长卷中的画面
};
```

| 1 | `night` | 一 · 孤舟夜泊 |
| 2 | `yixing` | 二 · 宜兴 |
| 3 | `return` | 三 · 归去来兮 |
| 4 | `voyage` | 过场 · 万里长卷 |
| 5 | `jinshan` | 四 · 不系之舟 |

调试 hash 一律用 id：`#act=lamp&mode=visitor&heart=bamboo&night=porridge`。（替代 v3 的 `#ep1`–`#ep3`。）

## 五、开发里程碑

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| M0 · 搭架子 | Vite 工程、目录结构、从 v3 抽取 `core/` `ink/` `cut/`、字体自托管 | v3 的三段剧情在新架构下原样跑通 |
| M1 · 技术原型 | 灯影成字、千人画卷、4K 性能测试 | 灯影对任意物品组合都能拼出"舣"；千人场景在展厅同配置机器上 4K 稳定 60fps |
| M2 · 样板幕 | 第一幕"孤舟夜泊"完整实现（含分支、转场、游客版计时） | 五拍、T3/T6 转场、跳过、无操作推进全部可用 |
| M3 · 展厅外壳 | 待机、众人长卷、讲解员快捷键、重载与恢复 | 连续运行 10 小时无内存增长、无卡死 |
| M4 · 全部幕 | 其余七段 | 游客版总时长 9–11 分钟 |
| M5 · 画卷与打磨 | 个人长卷演出、评审对比、音频 | 现场彩排 |

内容线并行进行：剧本分镜 → 诗文核对 → 吟诵录音 → 人物三个年龄段设计稿。
